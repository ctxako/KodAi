# KodAi Vision

## One-line thesis

KodAi is a local-first Apple-native AI workspace for projects, memory, files, and focused execution.

It will not become another generic chatbot. It will become a private thinking environment where conversations, project notes, tasks, summaries, decisions, and files all stay connected. 

## Product identity

KodAi is a **local assistant in a glass box**.

It is built around a simple idea:

> The assistant should understand what you are working on, preserve the important parts, and help move each project forward without forcing you to re-explain everything every session.

KodAi should feel less like a generic chatbot and more like a private operating layer for thinking and building.

It should be able to act as a:

- consultant when the user needs direction
- teacher when the user needs to understand something
- explorer when the user is brainstorming
- critic when the user needs honest feedback
- reaffirming assistant when the user needs confidence in a decision

The product identity is calm, local, private, and inspectable: an Apple-native AI workspace where the assistant lives inside a focused glass interface, remembers what matters, and helps the user continue the work.


## Core principles

### 1. Local-first by default

KodAi should prefer on-device Apple Intelligence and local storage whenever possible.

The app should avoid unnecessary network dependency, API keys, and external services unless a future feature explicitly requires a larger model or web access.

### 2. Projects over loose chats

A chat is temporary.

A project is persistent.

Loose chats can exist for quick thoughts, tests, questions, and one-off conversations. They should not be erased automatically, but they should also not become the main long-term memory system.

Every useful conversation should have a path into a project.

If a loose chat produces something worth keeping — a decision, summary, task, idea, file note, or plan — KodAi should help move that value into the right project.

Each project should contain its own summary, files, tasks, decisions, and active context.

The rule is simple:

> Loose chats are for thinking in the moment. Projects are for preserving what matters.


### 3. Memory through compression, not hoarding

KodAi should not blindly save everything forever.

Memory should be created by summarizing, compressing, and organizing useful information into durable project knowledge.

The app should distinguish between:

- raw chat history
- active working context
- project summaries
- important decisions
- archived notes
- reusable facts

### 4. Native Apple experience

KodAi should feel like it belongs beside Notes, Reminders, Calendar, Finder, and Xcode. Like its Apple's proprietary app that utilizes its on device model to become a useful entity. 

The interface should be calm, fast, readable, and spatially clear.

Visual style should support thinking instead of competing with it.

### 5. The assistant should expose its work

KodAi should make its own process inspectable.

The user should be able to see:

- what context was used
- what project memory was injected
- what files were referenced
- what assumptions were made
- what tasks were created
- what changed after a response

This is especially important because KodAi is also a learning project for building AI systems.

### 6. Inspection should feel like exploration

KodAi should expose model behavior without collapsing into a conventional diagnostics dashboard. Inspection views should feel like expeditions through the model's decisions: calm, spatial, tactile, and rewarding to explore.

The educational layer should:

- translate probability, uncertainty, sampling, and context into honest visual metaphors
- explain the active decision in plain language before presenting raw metrics
- keep raw tokens and model data available as a deeper layer rather than hiding them
- distinguish measured data encodings from decorative or compositional movement
- reveal complexity progressively so curiosity is rewarded without overwhelming the user

## Visual language: a nocturnal field guide

KodAi's inspection surfaces should combine the restraint of an Apple-native interface with the atmosphere of scientific fieldwork at night. Midnight backgrounds, luminous currents, restrained glass, and warm uncertainty accents should make the system feel alive without turning it into spectacle.

The river is a signature expression of this direction: generated text becomes a journey through possible next tokens. Wider water means more possibilities, brighter paths mean stronger probability, tributaries show alternatives, and a distinct fork shows when sampling chose exploration over the strongest prediction. Every visual mapping should be teachable, accessible without color alone, and technically faithful to the local model's telemetry.

## Target user

The first target user is the builder.

KodAi is for someone who is learning, coding, organizing, experimenting, shipping small apps, and trying to build a private AI assistant that improves over time. As an AI engineering student, I want the app skin-less, all fuctions can be viewable. 

The app does not need to start broad. It should become excellent for one serious builder first.

## What KodAi is not

KodAi is not:

- a generic ChatGPT clone
- a cloud-first SaaS assistant
- a social app
- a messy note dump
- an everything-at-once automation tool
- an app that hides all reasoning behind a black box

## Long-term vision

In its mature form, KodAi becomes a private project operating system.

A project could contain:

- chats
- source files
- research
- summaries
- tasks
- decisions
- challenges
- experiments
- model notes
- context packs
- archived work

The assistant should help maintain that system automatically.

## Platform vision

### macOS

The macOS app is the command center.

It should focus on:

- project organization
- large chat views
- file context
- developer workflow
- research
- memory inspection
- multiwindow or sidebar-heavy workflows

### iOS

The iOS app should become the pocket companion.

It should focus on:

- quick capture
- short follow-ups
- reminders
- summaries
- project status
- lightweight assistant interactions
- widgets and shortcuts later

macOS and iOS should share the same product brain, but their interfaces should not be forced to be identical.

## North Star

KodAi is successful when opening the app feels like returning to a living workspace that remembers what matters, knows what is active, and helps continue the work without wasting time.
